
## Engineering Workflow

For end-to-end engineering work, follow:

    Discuss → Plan → Implementation Gate → Implement → Verify

- **Discuss** — understand the request and resolve meaningful ambiguity.
- **Plan** — use `plan` when understood work still requires material product or technical decisions before implementation.
- **Implementation Gate** — implementation may begin only when the authoritative work is sufficiently defined, required decisions and blockers are resolved, and the project's workflow considers it approved or executable.
- **Implement** — implement the authorized work, decomposing it when necessary. Test and review the change before final verification.
- **Verify** — establish with the strongest practical evidence that the completed work satisfies the agreed contract.

The authoritative work may be represented by a Proposal, Spec, issue, ticket, accepted plan, or another project-defined artifact.

Use the project's existing statuses, labels, approvals, or equivalent workflow conventions to determine whether the Implementation Gate has passed. Do not require a specific artifact type or status name.

Skip `plan` when the work already satisfies the Implementation Gate.

Enter or return to `plan` when implementation would otherwise require inventing a material product, scope, domain, architectural, interface, compatibility, or other contract decision.

For end-to-end requests, continue through the workflow automatically. For scoped requests, perform only the requested stage.
