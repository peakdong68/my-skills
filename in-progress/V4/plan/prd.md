
Use a PRD only when the Proposal does not sufficiently define the product contract.

The PRD defines what the system should do, not how it should be implemented.

Use it to clarify material:

- behavior
- scope
- non-goals
- requirements
- acceptance criteria

Keep it proportional to the work.

Do not include technical design, implementation structure, or engineering choices. Those belong in the RFC or implementation.

Material product ambiguity must be resolved before the plan can become ready for implementation.

The user is the authority for unresolved product behavior and value judgments unless they explicitly delegate that authority.
