# 计划评审（Plan Review）

在实施之前评审相关的规划工件。

沿三个独立维度评估规划集合：

- **标准（Standards）** — 对已接受的 ADR、适用的 RFC、既定领域语言和项目约束的遵从程度。
- **规范（Spec）** — 对权威产品契约或工作契约（例如提案、PRD、已批准的 Spec 或等效项目工件）的覆盖程度。
- **架构（Architecture）** — 边界、职责、依赖关系、接口和系统关系的一致性。

仅报告实质性发现和权衡。

## 决策

计划评审可以接受所提议的设计、要求修订，或予以拒绝。

在拥有相应发现的工件中解决这些发现。

已有契约、已接受的决策和既定约束可直接解决已由它们管辖的问题。

涉及未解决的产品、业务、兼容性、成本、风险、架构或其他价值判断的重大选择，属于用户的决策范畴，除非该权限已被明确授予。

若权限已被授予，则自行做出决策，并保留实质性推理过程。

对于工作中涉及的 RFC：

- 已接受的设计 → 按照项目的 RFC 约定将其标记为已接受（accepted）或已批准（approved）
- 已拒绝的设计 → 按照项目的约定将其标记为已拒绝（rejected）
- 需要修订 → 在再次评审之前保持其非权威状态

当一项已接受的决策创建或变更了持久的架构约束时，在适当情况下通过 `domain-modeling` 将其作为 ADR 予以保留。

## 门禁（Gate）

当满足以下条件时，规划集合通过门禁：

- 标准、规范和架构不存在未解决的实质性发现
- 必需的决策已解决
- 实施所需的 RFC 已被接受或批准
- 已接受的决策已在其权威工件中得到体现
- 持久的决策在适当时已予以保留
- 实施可以在不凭空创造实质性产品行为或架构的情况下继续进行

若门禁通过，则按照项目的工作流约定将权威工件标记为已批准（approved）或可实施（ready for implementation）。

若未通过，则将工作保留在规划阶段，修订相应工件，并再次进行评审。

常规的实施细节可以保持开放。
