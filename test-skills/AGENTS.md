## 代码开发工作流及硬约束

默认工程流程：

```text
Discuss → Plan → Implement → Verify
```

工程任务按 `./engineering.md` 路由和编排。

- 仅 `/implement` 或用户明确输入 **“执行实现”** 视为执行授权；“确认”“可以”“同意”等仅表示审批。
- 权威工作项可以是提案、规范、问题、工单、已接受的计划或其他项目定义的工件。
- 使用项目现有的状态、标签、审批或其他工作流约定来确定实施门禁是否已通过。不要要求特定的工件类型或状态名称。
- 当工作已满足实施门禁时，跳过 `plan`（计划）。
- 当实施否则需要发明重大的产品、范围、领域、架构、接口、兼容性或其他契约决策时，返回 `plan`（计划）。

对于端到端请求，自动继续执行工作流。对于限定范围的请求，仅执行所请求的阶段。
