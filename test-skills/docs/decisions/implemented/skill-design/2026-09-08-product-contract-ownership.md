# 产品需求优先由现有合同承载

## 背景与决定

原 prd.md 将 Proposal 信息不足作为使用 PRD 的前提，暗含必须存在 Proposal，且容易将产品信息缺口转化为新增文档要求。

优先在已有权威工件中澄清产品合同；用户明确要求或合同需要独立拥有时才创建独立 PRD。位置和格式遵循项目注册及既有文档；PRD 不随关联变更记录移动。

## 理由与影响

不再要求先有 Proposal，也不为每个需求缺口生成 PRD。保留独立产品需求文档的用途，同时区分已确定需求、提议行为和未决事项，避免模型推测被写成已批准需求。生成文档不授予批准或执行权限。
