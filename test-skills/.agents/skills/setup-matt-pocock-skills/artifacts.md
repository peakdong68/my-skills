## 生效范围

本约定管理工程工件的查找、创建、更新和生命周期，不要求生成全部工件。日常文档治理直接处理并检查；实质改变工程合同的修改按工程流程处理。

## 新工件归属

| 工件或信息 | 位置与规则 |
| --- | --- |
| Proposal / 总体及阶段方案 / 变更决定 | `docs/decisions/proposed/<分类>/日期-主题.md`；提案与交付理由由同一记录拥有，不另建同义 Note |
| 独立技术设计 RFC | `docs/rfcs/`；需要独立评审、复用或演进时拆出，由提案引用 |
| 独立行为合同 Spec | `docs/specs/`；明确需要时创建，优先更新同一工作已有 Spec |
| 持久决定 / ADR | 优先由变更记录承载；需要独立 ADR 时在此登记具体位置及职责边界 |
| Issue / Ticket / 阶段和模块进度 | 按 `docs/agents/issue-tracker.md` 配置；本地模式默认 `.scratch/<feature-slug>/issues/<NN>-<slug>.md`，实际配置优先 |
| PRD 或其他已有工件 | 登记项目已有位置；本方法不要求另建 PRD，未配置时由现有权威产品工件拥有需求 |

文件有真实内容时才创建。分类读取 `docs/decisions/config.json`；项目规范和同类在维护工件优先作为格式依据。实际命名及格式参考在相应位置规则中补充。

## 生命周期与批准

变更记录遵循 `docs/decisions/README.md`：proposed 表示尚未或部分交付，implemented 表示所记范围已交付并验证，rejected 表示否决。批准依据和执行授权分别遵循项目约定。

独立 RFC、Spec、ADR 不随变更记录移动。在此登记它们已有的审阅、批准和替代约定；未规定时不从文件生成推断批准。Issue/Ticket 状态由跟踪器配置管理。

总体提案链接阶段和模块工作项，各工程单元按需运行工程循环。阶段完成还需集成与阶段验收；总体范围全部交付前保持 proposed。

## 维护

重新 setup 默认检查和补齐配置，已有差异保留并报告。明确选择新位置时更新本注册表与项目指令；只有授权迁移时才移动历史工件、转换状态并修复链接。注册不新增执行权限。
