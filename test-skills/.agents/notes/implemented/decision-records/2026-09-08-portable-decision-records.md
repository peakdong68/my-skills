# 决策管理资源与项目历史分离

部分替代说明：本文的固定分类选择已由 [按项目分类组织提案与交付记录](./2026-09-08-project-configured-record-lifecycle.md) 替代。下文保留原决定依据；可复用资源、项目历史分离及重复 setup 不覆盖的规则仍有效。

## 背景

首次落实将 workflow、skills 等本仓库特征用作通用分类，混淆了可复用管理工具与项目历史。用户指出该设计无法直接服务其他业务项目。

## 决定

通用分类为 feature、bug-fix、simplification、architecture、process、testing。规范、模板和脚本放入 setup 的资源目录，按需部署至目标项目；本仓库决策文件独立保留，不随初始化复制。目标项目已有记录体系时优先复用。

## 理由与替代方案

放弃以本仓库技能与工作流划分类别的方式，它将项目特征变成了通用约束。保留本仓库历史，避免为了资源通用化删除已接受决定的依据。资源随现有 setup 选配，不新增必经技能或安装门禁。

## 影响

通用资源是可复用源，部署后成为项目副本。更新需保留项目定制，不能自动覆盖。本仓库使用相同资源作为本地部署，通用修改需同步；批准与执行权限仍由各项目拥有。

重复执行 setup 默认检查和补齐兼容的缺失配置，相同文件跳过，不同文件保留并报告；明确请求升级时才合并。索引按项目现有记录生成，不重置历史。此规则包含三个脚本，补齐时需检查伴随脚本兼容性。

## 依据与关联
