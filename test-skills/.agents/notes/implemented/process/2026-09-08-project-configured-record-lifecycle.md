# Agent Note: 按项目分类组织提案与交付记录

Status: implemented

## 问题

本记录最初针对当时的通用 Notes 资源：固定分类被认为无法表达各项目自身交付对象，批准状态也未覆盖提案到部分实施再到交付的生命周期。后来项目采用 DSH Skill 后，分类与生命周期规则按新属主更新。

## 决定

本记录原先采用目标项目 `config.json` 动态分类及三阶段记录布局。该机制现由 [DSH 统一 Notes 决定](./2026-10-29-setup-planning-dsh-notes.md) 取代：Notes 使用 DSH 固定类别与生命周期，不再读取项目类别配置。此历史记录保留当时采用动态分类的理由与迁移依据。

当时的实现沿用项目文档风格，工具只检查元数据、路径、链接和索引，不强制章节。当前统一格式与机械检查由 DSH Skill 拥有；普通文档治理仍不另启工程循环，实质合同修改仍按工程工作流处理。

## 备选方案

当时放弃硬编码类别，是因为旧资源将特定项目语境误当作通用分类；放弃只用 Draft/Accepted 等批准状态描述记录，是因为已批准但未交付与已交付需要区分。现在项目主动采用 DSH 固定类别；批准、执行授权和 Note 生命周期仍是不同事实。

## 后果

关于总体提案本身使用 proposed 生命周期的默认规则，已由 [明确实施工作项与提案归属](./2026-09-08-work-item-and-proposal-boundaries.md) 调整为工作项管理状态、Note 管理交付生命周期；工作跟踪器是可选的，无跟踪器时由当前任务承载工作项。

DSH 固定 class 和生命周期由 Skill 脚本校验；项目不再新增动态类别配置。生命周期迁移需更新文件路径和链接。本仓库保留旧决定理由，但旧动态配置和索引机制已被新 Notes 契约取代。

## 依据与关联

2026-09-08 本任务会话中用户确认方案并要求落实；无独立会话链接。

部分替代 [可复用资源与项目历史分离](./2026-09-08-portable-decision-records.md) 中关于固定分类及旧生命周期的内容，其余副本归属和防覆盖规则继续适用。

当前 Notes 规则见 [DSH Skill](../../../../.agents/skills/write-agent-notes/SKILL.md)；Setup 的项目选择与迁移说明见 [Agent Notes setup](../../../../skills/user-invoked/setup-agent-skills/decision-records.md)。

历史验证曾用旧索引生成器、checker 与自测脚本覆盖空资源部署、自定义分类、生命周期、必填依据、失效链接及索引新鲜度；这些工具已移除，记录格式和目录当前由 DSH Skill 校验。重复 Setup 防覆盖仍是技能执行约束，不是安装器保证。
